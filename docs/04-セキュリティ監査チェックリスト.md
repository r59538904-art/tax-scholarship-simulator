# セキュリティ監査チェックリスト

**対象システム**：住民税・所得税・国民健康保険・JASSO奨学金 判定シミュレーター
**監査日**：2026-08-14
**構成**：静的HTML／CSS／JavaScript のみ。サーバ・DB・ネットワーク通信なし。依存パッケージ0件
**永続化**：入力内容は保存しない。保存するのは配色の設定（`localStorage` のキー `tk-theme`）1件のみ

---

## 0. 監査の前提とリスク評価基準

### 0.1 このシステムが扱う情報

| 情報 | 機微度 | 保持期間 |
|---|---|---|
| 給与収入・年金収入・事業所得・株式の譲渡益 | **高**（要配慮に準ずる） | ページを閉じるまで（メモリのみ） |
| 家族構成・年齢・続柄 | **中** | 同上 |
| **障害者区分**（本人・家族） | **最高**（要配慮個人情報） | 同上 |
| ひとり親・寡婦・生活保護受給の有無 | **最高**（要配慮個人情報） | 同上 |
| 居住する市区町村 | 中 | 同上 |

障害・生活保護・ひとり親は個人情報保護法上の**要配慮個人情報**にあたります。
本システムの最大のセキュリティ設計判断は **「これらを一切外に出さず、一切保存しない」** ことです。

### 0.2 リスクレベルの定義

| レベル | 意味 | 対応方針 |
|---|---|---|
| 🔴 **重大** | 要配慮個人情報の漏えい・改ざんに直結 | ただちに是正 |
| 🟠 **高** | 個人情報の漏えい、または誤った税額による実害 | 計画的に是正 |
| 🟡 **中** | 単独では実害が小さいが、組み合わせでリスクになる | 次回改修で是正 |
| 🟢 **低** | 予防的・将来の機能追加に備えるもの | 任意 |
| ⬜ **N/A** | 本構成では該当しない | 構成変更時に再評価 |

### サーバ配信する場合に必須の設定

```
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self';
                         img-src 'self' data:; connect-src 'none';
                         base-uri 'none'; form-action 'none'; frame-ancestors 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: geolocation=(), camera=(), microphone=(), interest-cohort=()
Cache-Control: no-store        （HTML。静的アセットは immutable）
```

`connect-src 'none'` を入れることで、**万一コードが混入しても外部送信できない**という
多層防御になります（本システムの設計方針をブラウザ側で強制できる）。

### 8.3 総括

**🔴重大レベルのリスクはすべて適合しており、現時点で是正が必要な重大な脆弱性はありません。**

本システムのセキュリティ上の本質は、機能を足すことではなく **機能を持たないこと** で
達成されています。

- 外部に**送らない** → 通信経路での漏えいが起こりえない
- 端末に**保存しない** → 共用PCでも残存しない
- 依存パッケージを**持たない** → サプライチェーン攻撃の面がない
- 認証を**持たない** → 認証情報の漏えいが起こりえない
- 自由入力欄を**持たない** → XSSの入口がない

要配慮個人情報（障害・生活保護・ひとり親）を扱うツールとして、この設計は妥当です。

一方で、**税務ツール固有のリスク（T分類）** のほうが実害に直結します。
とくに T-11（都道府県データの検証範囲）は年次の保守で継続的に潰していく必要があります。

### 8.4 構成を変更する場合の再監査トリガー

次のいずれかを行う場合は、本チェックリストを最初から実施し直してください。

- [ ] Webサーバで配信する（→ C・L・V分類を全面再評価）
- [ ] 入力内容を保存する機能を追加する（→ A・D分類を全面再評価）
- [ ] 外部APIを呼ぶ（→ D-01・D-02 が根本から変わる）
- [ ] 自由入力欄（氏名・メモなど）を追加する（→ I-09 が実リスク化）
- [ ] 第三者ライブラリを導入する（→ V-01・V-02 が発生）
- [ ] 解析タグを入れる（→ L-02・D-01 に抵触。**推奨しない**）
