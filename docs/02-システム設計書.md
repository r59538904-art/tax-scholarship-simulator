# システム設計書

**システム名**：住民税・所得税・国民健康保険・JASSO奨学金 判定シミュレーター
**版数**：1.0（2026-08-14）

---

## 1. システム概要

### 1.1 目的

学生本人・保護者・単身者が、自分の収入と控除を入力するだけで次の4つを判定できるようにする。

1. **所得税**の年税額（課税されるか／いくらか）
2. **住民税**の均等割・所得割それぞれの課税／非課税と税額
3. **国民健康保険料の軽減割合**（7割・5割・2割・なし）
4. **JASSO給付奨学金・授業料等減免の支援区分**（第Ⅰ〜第Ⅳ区分）

とくに **「住民税の所得割が非課税かどうか」が奨学金の支援区分を決める** という関係を、
利用者が自分の数字で確認できることを最重要の目的とする。

### 1.2 利用形態

| 項目 | 内容 |
|---|---|
| 配信形態 | ローカルファイル（`index.html` をブラウザで開く） |
| サーバ | **なし**（静的ファイルのみ。Webサーバも不要） |
| ネットワーク通信 | **なし**（外部リクエストを一切行わない） |
| データ保存 | **なし**（Cookie・localStorage・IndexedDB を使用しない） |
| 認証 | **なし**（個人を識別しないため不要） |
| 想定利用者 | 個人（学生・保護者・単身者）。同時利用者という概念はない |

### 1.3 対象範囲

| 対象年分・年度 | 内容 |
|---|---|
| 令和7年分（2025年）の所得 | → 令和8年度の住民税・国民健康保険、2026年度のJASSO支援区分 |
| 令和8年分（2026年）の所得 | → 令和9年度の住民税・国民健康保険（**見込み**） |

### 1.4 用語

| 用語 | 定義 |
|---|---|
| 合計所得金額 | 繰越控除を適用する**前**の各種所得の合計。均等割の非課税判定・扶養判定に使う |
| 総所得金額等 | 繰越控除を適用した**後**の金額。所得割の非課税判定・課税標準に使う |
| 課税標準額 | 総所得金額等 − 所得控除（1,000円未満切捨て） |
| 支給額算定基準額 | 課税標準額×6％−（市町村民税の調整控除額＋調整額）。JASSOの区分を決める |
| 軽減判定所得 | 国保の軽減判定に使う所得。住民税の所得とは扱いが一部異なる |
| 級地区分 | 生活保護法に基づく地域区分（1〜3級地）。住民税均等割の非課税限度額に影響 |
| 生計維持者 | JASSOの用語。原則として父母。奨学金の区分はこの人たちの住民税で決まる |

## 2. 機能要件

### 2.1 機能一覧

| ID | 機能 | 概要 |
|---|---|---|
| F-01 | 立場の選択 | 学生本人／夫婦（2人）／ひとり を選び、入力欄の呼び名と表示項目を切り替える |
| F-02 | 奨学金判定の要否切替 | JASSOの判定を行うかどうかを独立して切り替える |
| F-03 | 地域の設定 | 都道府県・市区町村を選択。級地区分・均等割額・所得割税率を自動設定 |
| F-04 | 税率の手動調整 | 自治体独自の超過課税・減税に対応するため均等割額・税率を上書き可能 |
| F-05 | 世帯構成の登録 | 世帯員を1人ずつ登録し、扶養区分を自動判定 |
| F-06 | 人数の自動集計 | 非課税限度額の判定人数・扶養親族数・国保の被保険者数を自動算出 |
| F-07 | 収入の入力 | 総合課税（給与・年金・事業・不動産・雑）＋分離課税（株式・不動産譲渡・先物・退職・山林） |
| F-08 | 繰越控除の入力 | 上場株式等の譲渡損失・純損失・雑損失 |
| F-09 | 所得控除の入力 | 社会保険料・小規模企業共済等・生命保険料・地震保険料・医療費・雑損・その他 |
| F-10 | 人的控除の自動判定 | 配偶者・扶養・特定親族特別・障害者控除を世帯構成から自動計算 |
| F-11 | 控除の条件ロック | 所得条件を満たさない控除を自動的に選択不可にし、理由を表示 |
| F-12 | 所得税の計算 | 総合課税＋分離課税＋山林（5分5乗）＋退職、復興特別所得税を含む |
| F-13 | 住民税の計算 | 均等割・所得割を分離計算。調整控除・所得割額の調整措置を含む |
| F-14 | 非課税判定 | 均等割（合計所得金額）と所得割（総所得金額等）を別々に判定 |
| F-15 | 国保の軽減判定 | 軽減判定所得を算出し、7割・5割・2割を判定。計算過程を表示 |
| F-16 | JASSOの区分判定 | 支給額算定基準額を算出し、第Ⅰ〜Ⅳ区分と「あといくらで該当するか」を表示 |
| F-17 | 家族単位の詳細計算 | 世帯員1人ずつについて本人の所得税・住民税も計算 |
| F-18 | 結果のPDF出力 | 印刷CSSでA4に整形し、ブラウザの「PDFに保存」で出力 |
| F-19 | 制度の解説表示 | 均等割と所得割の違いなどを表形式で解説 |
| F-20 | 出典の表示 | 全数値の出典をURL付きで表示 |

### 2.2 主要な業務ルール（抜粋）

| ルール | 内容 |
|---|---|
| BR-01 | 均等割の非課税判定は**合計所得金額**（繰越控除前）、所得割は**総所得金額等**（繰越控除後）で行う |
| BR-02 | 扶養親族等がいる場合の加算額は均等割＋21万円（1級地）、所得割＋32万円と**異なる** |
| BR-03 | 給与所得は法定表どおり**4,000円単位に丸めて**計算する |
| BR-04 | 課税標準額は1,000円未満切捨て、所得割額・年税額は100円未満切捨て |
| BR-05 | 所得控除は総所得金額→分離課税→山林→退職の順に充当する |
| BR-06 | 退職所得の住民税は現年分離課税のため翌年度の課税標準・非課税判定に含めない |
| BR-07 | 市町村民税の所得割が非課税なら支給額算定基準額は0円＝必ず第Ⅰ区分 |
| BR-08 | 国保の軽減判定所得は所得控除を引かず、分離譲渡は特別控除前で見る |
| BR-09 | 政令指定都市は所得割 市8％／道府県2％、調整控除 市4％／道府県1％、JASSOは調整控除に4分の3 |

```
 ┌─────────────────────────────────────────────────┐

 │  DOM操作・表示文言・イベント                      │

                     │ 依存（一方向）
 ┌───────────────────▼─────────────────────────────┐

 │  税額計算・判定ロジック。DOMを一切知らない        │
 └───────────────────┬─────────────────────────────┘
                     │ 依存（一方向）
 ┌───────────────────▼─────────────────────────────┐

 │  税率表・控除表・地域マスタ。ロジックを持たない   │
 └─────────────────────────────────────────────────┘
```

**設計の要点**：`calc.js` は DOM に触れないため、Node.js からそのまま呼び出せる。
これにより 196 件の計算テストをブラウザなしで高速に回せる（実行時間 1秒未満）。同じ仕組みで、総当たり検証 636,008 件と網羅監査 471,860 件も Node だけで回している。

```
        │ salaryEarners  │            │────────────────────│
        │ otherIncome    │            │ id / lo / hi / ratio│
        │ landSpecialDed │            └─────────────────────┘
        │ senjusha       │
        └────────────────┘
```

**関係の要点**

- `Calculation 1 : N Person`（A＝必須、B＝任意、詳細計算する世帯員＝0..N）
- `Person` のうち A・B は「生計維持者」、それ以外は「扶養判定の対象となる世帯員」
- `M_Prefecture 1 : N M_City`（都道府県コードで親子）
- マスタ（`M_*`）はすべて**読み取り専用**。利用者の入力で書き換わることはない
  （画面上の「税率の手動調整」は `Region` 側の値を上書きするだけでマスタは不変）

### 5.5 サーバ化する場合のRDBスキーマ案（参考）

現状は不要だが、複数端末での保存や統計が必要になった場合の設計案。

#### 正規化方針
- 第3正規形まで正規化。税制マスタは年分をキーに持たせて履歴を保持する
- 判定結果はマスタから再計算可能なため**保存しない**（導出項目を持たない）
- 個人情報は保存しない設計とし、保存するのは匿名の入力パラメータのみ

#### テーブル定義

```sql
-- 税制マスタ（年分ごとに1行。改正しても過去分を再現できる）
CREATE TABLE m_tax_year (
  income_year        SMALLINT     NOT NULL PRIMARY KEY,
  salary_min         INTEGER      NOT NULL,      -- 給与所得控除の最低保障額
  salary_min_cap     INTEGER      NOT NULL,      -- 最低保障が適用される収入上限
  dependent_limit    INTEGER      NOT NULL,      -- 扶養親族等の所得要件
  student_limit      INTEGER      NOT NULL,
  student_deduction  INTEGER      NOT NULL,
  spouse_upper       INTEGER      NOT NULL,
  tokutei_lower      INTEGER      NOT NULL,
  tokutei_upper      INTEGER      NOT NULL,
  source_url         TEXT         NOT NULL,      -- 出典（必須）
  effective_from     DATE         NOT NULL,
  CONSTRAINT ck_year CHECK (income_year BETWEEN 2020 AND 2100)
);

-- 基礎控除（年分×所得区分）
CREATE TABLE m_basic_deduction (
  income_year   SMALLINT NOT NULL REFERENCES m_tax_year(income_year),
  upper_income  BIGINT   NOT NULL,               -- 合計所得金額の上限（最終行は NULL 相当の大きな値）
  amount        INTEGER  NOT NULL,
  PRIMARY KEY (income_year, upper_income),
  CONSTRAINT ck_amount CHECK (amount >= 0)
);

-- 所得税の速算表
CREATE TABLE m_income_tax_bracket (
  upper_taxable BIGINT  NOT NULL PRIMARY KEY,
  rate          NUMERIC(5,4) NOT NULL,
  subtraction   INTEGER NOT NULL,
  CONSTRAINT ck_rate CHECK (rate BETWEEN 0 AND 1)
);

-- 都道府県マスタ
CREATE TABLE m_prefecture (
  pref_code     CHAR(2)      NOT NULL PRIMARY KEY,   -- JIS X 0401
  pref_name     VARCHAR(8)   NOT NULL UNIQUE,
  kintou_add    INTEGER      NOT NULL DEFAULT 0,     -- 均等割の超過課税
  shotoku_rate  NUMERIC(6,4) NOT NULL DEFAULT 4.0,   -- 道府県民税所得割
  surtax_name   VARCHAR(60),
  surtax_until  DATE,                                -- 課税期間の終期
  source_url    TEXT         NOT NULL
);

-- 市区町村マスタ
CREATE TABLE m_city (
  city_code     CHAR(5)      NOT NULL PRIMARY KEY,   -- JIS X 0402
  pref_code     CHAR(2)      NOT NULL REFERENCES m_prefecture(pref_code),
  city_name     VARCHAR(20)  NOT NULL,
  kyuchi        SMALLINT     NOT NULL,               -- 生活保護法の級地区分
  is_seirei     BOOLEAN      NOT NULL DEFAULT FALSE,
  kintou_add    INTEGER      NOT NULL DEFAULT 0,
  kintou_fixed  INTEGER,                             -- 減税等で直接指定する場合
  shotoku_rate  NUMERIC(6,4),                        -- NULL なら標準（政令市8／一般6）
  note          VARCHAR(120),
  CONSTRAINT ck_kyuchi CHECK (kyuchi IN (1,2,3)),
  CONSTRAINT uq_city UNIQUE (pref_code, city_name)
);

-- JASSO 支援区分
CREATE TABLE m_jasso_kubun (
  kubun_id   SMALLINT NOT NULL PRIMARY KEY,
  lower_amt  INTEGER  NOT NULL,
  upper_amt  INTEGER  NOT NULL,
  grant_num  SMALLINT NOT NULL,      -- 支給割合の分子
  grant_den  SMALLINT NOT NULL,      -- 支給割合の分母
  CONSTRAINT ck_range CHECK (lower_amt < upper_amt)
);

-- 匿名の入力ログ（統計用。個人情報は持たない）
CREATE TABLE t_calculation_log (
  calc_id       BIGSERIAL PRIMARY KEY,
  calculated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  income_year   SMALLINT    NOT NULL REFERENCES m_tax_year(income_year),
  city_code     CHAR(5)     REFERENCES m_city(city_code),
  mode          VARCHAR(10) NOT NULL,
  salary_band   SMALLINT,             -- 100万円刻みに丸めた帯（生の金額は保存しない）
  jasso_kubun   SMALLINT REFERENCES m_jasso_kubun(kubun_id),
  kokuho_level  SMALLINT,
  CONSTRAINT ck_mode CHECK (mode IN ('student','couple','single'))
);
```

#### インデックス設計

| インデックス | 対象 | 種別 | 目的 |
|---|---|---|---|
| `pk_m_city` | `m_city(city_code)` | 主キー（B-Tree） | 単一取得 |
| `ix_m_city_pref` | `m_city(pref_code, city_name)` | 複合B-Tree | 都道府県で絞って市区町村を並べる（画面のプルダウン） |
| `ix_m_city_kyuchi` | `m_city(kyuchi)` | B-Tree | 級地別の集計 |
| `pk_m_basic_ded` | `m_basic_deduction(income_year, upper_income)` | 主キー | 年分＋所得で範囲検索（`WHERE income_year=? AND upper_income>=? ORDER BY upper_income LIMIT 1`） |
| `ix_log_date_city` | `t_calculation_log(calculated_at DESC, city_code)` | 複合B-Tree | 期間×地域の集計 |
| `ix_log_kubun` | `t_calculation_log(jasso_kubun) WHERE jasso_kubun IS NOT NULL` | 部分インデックス | 区分別集計。NULLを除いてサイズ削減 |

#### パフォーマンス考慮

| 観点 | 方針 |
|---|---|
| マスタの読み出し | 全件でも数十KB。**起動時に全件メモリキャッシュ**しDBアクセスを0回にする |
| 階段テーブルの検索 | 上限値をキーにした範囲検索。件数が10件未満なのでフルスキャンでも十分 |
| ログの肥大化 | 月次パーティション（`calculated_at` でRANGE分割）。13か月より前は削除 |
| 集計クエリ | ログは追記のみ。集計はマテリアライズドビューを日次リフレッシュ |
| N+1回避 | 市区町村のプルダウンは都道府県ごとに1クエリでまとめて取得 |

#### 制約条件

| 種別 | 内容 |
|---|---|
| 主キー | すべてのテーブルに設定。マスタは自然キー（JISコード）を採用 |
| 外部キー | `m_city.pref_code` → `m_prefecture`、ログ → 各マスタ。削除は `RESTRICT` |
| CHECK | 級地は1〜3、税率は0〜1、区分の下限＜上限、金額は非負 |
| UNIQUE | `m_prefecture.pref_name`、`m_city(pref_code, city_name)` |
| NOT NULL | 出典URL（`source_url`）は**必須**。出典のない税制データを登録できないようにする |

## 7. セキュリティ対策

詳細は `04-セキュリティ監査チェックリスト.md` に譲り、ここでは設計上の方針を示します。

| 脅威 | 対策 | 実装状況 |
|---|---|---|
| 入力データの漏えい | **外部通信を一切行わない**（fetch/XHR/WebSocket/画像の外部参照なし） | ✅ 実装済み |
| 端末に残ったデータの閲覧 | **保存しない**（Cookie・localStorage・sessionStorage・IndexedDB 不使用）。再読込で消える | ✅ 実装済み |
| XSS（表示時のスクリプト混入） | 画面に出す文字列は `esc()` でHTMLエスケープ。数値は `toLocaleString` を通す | ✅ 実装済み |
| 第三者ライブラリ由来の脆弱性 | **依存パッケージ0件**。npm も CDN も使わない | ✅ 実装済み |
| 改ざんされたファイルの実行 | ローカルファイルのため配布経路の管理が対策。サーバ配信時はCSPとSRIを付与 | ⚠️ 配信時に要対応 |
| PDF経由の情報流出 | PDFは利用者が明示的に操作したときだけ生成。自動送信はしない | ✅ 実装済み |
| 誤った税額による損害 | 全数値に出典を表示し、「概算・目安」「自治体で確認」を明記 | ✅ 実装済み |

### 8.2 更新手順（税制改正時）

```
1. 一次資料（国税庁・総務省・厚労省・JASSO）で数値を確認し、URLを控える
2. data.js の該当テーブルを更新し、SOURCES に出典を追加／更新する
3. verify.js / verify-calc.js に「その改正を検証するテスト」を先に書く
   （期待値は実装から逆算せず、一次資料から手計算した値を直書きする）
4. node test/verify.js と node test/verify-calc.js を実行し、全件パスすることを確認
5. 自治体の公式計算例が出ていれば、それも回帰テストに追加
6. node test/audit.js で不変条件・単調性が崩れていないことを確認
7. node test/browser-check.js を実行し、画面・配色・スマホ幅・PDF出力を確認
8. index.html の「税制改正のポイント」表と README を更新
9. ヘッダの「最終更新」を書き換える
```

**原則**：`SOURCES` に出典のない数値をコードに入れない。
出典が確認できない項目は「見込み」フラグを立てるか、画面で手動入力できるようにする。

## 9. 技術選定理由

### 9.1 選定結果

| レイヤ | 採用技術 | バージョン |
|---|---|---|
| 実行環境 | ブラウザ（Chrome / Edge / Firefox / Safari） | 直近2年程度 |
| 言語 | 素のJavaScript（ES5相当＋一部ES2015） | — |
| スタイル | 素のCSS（カスタムプロパティ、`@media print`） | — |
| ビルド | **なし** | — |
| 依存パッケージ | **0件** | — |
| テスト実行 | Node.js（標準機能のみ） | v24 |
| ブラウザ自動検証 | Chrome DevTools Protocol（Nodeの標準WebSocket） | — |
| PDF生成 | ブラウザの印刷機能＋印刷用CSS | — |

### 9.2 選定理由

#### なぜフレームワーク（React / Vue など）を使わないか

| 観点 | 判断 |
|---|---|
| 配布のしやすさ | HTMLファイルをダブルクリックするだけで動く必要がある。ビルド成果物やCDNへの依存は「開かない」原因になる |
| 寿命 | 税制ツールは**毎年**手を入れる。5年後もフレームワークのバージョン差異に悩まされずに直せることを優先 |
| 依存の脆弱性 | 依存0件なら `npm audit` の対象がない。税額という機微な入力を扱うため攻撃面を最小にしたい |
| 規模 | 画面は1本の縦フロー、状態は数十項目。仮想DOMの恩恵より、素直な `innerHTML` 再描画のほうが読みやすい |
| **トレードオフ** | 差分描画をしないため大量再描画が起きるが、実測100ms未満で問題にならない。フォーム部品の再生成でフォーカスが飛ぶ箇所は個別に対処済み |

#### なぜサーバ・DBを持たないか

| 観点 | 判断 |
|---|---|
| プライバシー | 収入・家族構成・障害の有無は最も機微な情報。**送らない・持たない**のが最強の対策 |
| 法的責任 | 個人情報を保持しないため、漏えいリスクと管理義務そのものが発生しない |
| 可用性 | サーバ障害・通信断の影響を受けない |
| コスト | 運用費0円。個人が長期に維持できる |
| **トレードオフ** | 入力の保存・複数端末での共有ができない。→ PDF保存で代替 |

#### なぜ計算ロジックをDOMから分離したか

`calc.js` が DOM を知らないことで、**Node.jsから直接呼べる**。
結果として196件の計算テストが1秒未満で回り、税制改正のたびに安心して数値を差し替えられる。
これは税額計算ツールで最も重要な設計判断。

#### なぜPDFライブラリ（jsPDF等）を使わないか

| 観点 | 判断 |
|---|---|
| 日本語フォント | jsPDF等で日本語を出すには数MBのフォント埋め込みが必要。ローカル完結の方針と合わない |
| 品質 | ブラウザの印刷エンジンのほうが日本語の組版・改ページ制御が優秀 |
| 依存 | ライブラリ0件を維持できる |
| **トレードオフ** | 印刷ダイアログでの操作が1手増える。→ 画面上で手順を明示して対応 |

#### なぜ級地データを自動生成にしたか

1,719件を手で入力すると転記ミスが避けられず、検証もできない。
生成スクリプトにすることで、**公表されている団体数（1級地107・2級地200）と自動照合**でき、
数年後の指定替えにも再実行だけで追随できる。

#### なぜ Node の標準機能だけでブラウザ検証しているか

Playwright / Puppeteer を入れると依存が数百MBになり、CIのない個人環境では維持が難しい。
Node 24の標準 `WebSocket` で Chrome DevTools Protocol に直接つなぐことで、
**依存0件のまま**実ブラウザでのUI検証・スクリーンショット・PDF生成ができる。

### 9.3 検討したが採用しなかった案

| 案 | 不採用の理由 |
|---|---|
| TypeScript | ビルド工程が必要になる。型の恩恵より「ファイルを直接開ける」ことを優先。代わりにJSDoc相当のコメントとテストで担保 |
| Web Components | ブラウザ差異の検証コストに見合わない |
| localStorage への入力保存 | 機微な入力を端末に残すリスク。共用PCでの利用を考えると保存しないほうが安全 |
| Service Worker によるオフライン化 | そもそもローカルファイルなので不要 |
| 外部の税額計算API | 入力を外部送信することになり、プライバシー方針と矛盾する |
